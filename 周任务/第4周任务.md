   读不出这句话，就先别写。

## Day 2（11/04 周三 · 1.5h）二级指针实战

**学什么**
- `char **` 最常见的两个身份：**字符串数组**、**"改调用方的指针"**。
- **指针数组 vs 数组指针**：`int *a[3]` ≠ `int (*a)[3]`。读法一样，从内往外。

**动手**（今天全部写在 → `week4/day2_01.c`，一文件多段）

1. `const char *names[] = {"led", "uart", "i2c"};` 用 `const char **p = names;` 遍历打三个名字，**只用 `p++` 不解引用数组**。
2. 写 `void set_flag(const char **slot, const char *v)`：把 `slot` 指的东西换掉。
   调用 `const char *cur = "idle"; set_flag(&cur, "busy");` → 验证 `cur` 真变了。
   **这题和 Day1 第 2 题同一根骨头**：想改调用方的变量，就得把它的门牌交进去。
3. 一个文件里同时写 `int *arr_of_ptr[3]` 和 `int (*ptr_to_arr)[3]`，各打一次 `sizeof`，并注释解释数字为什么不同（8×3 = 24 vs 8）。
4. 编译 + 跑，零 warning。有 warning 先修，不许带着交。

## Day 3（11/05 周四 · 1.5h）函数指针：函数也有门牌

**学什么**
- 函数名就是它的门牌（跟数组名一样，会退化成指针）。
- `int (*op)(int, int)` 和 `int *op(int, int)` 完全是两回事——差一对括号，差一辈子。
- 为什么嵌入式爱它：**不知道要调哪个函数，但知道签名一样**。

**动手**（新文件 → `week4/day3_01.c`）

1. 写 `add` / `sub` / `mul` 三个函数，签名统一 `int f(int, int)`。
2. `int (*op)(int, int) = add;` 然后 `op(3,4)` / `(*op)(3,4)` 两种写法各打一次，**证明等价**。
3. 打一次 `printf("%p\n", (void *)add)` 和 `printf("%p\n", (void *)&add)`，证明**函数名和取地址是同一个数**。
4. 写 `int apply(int (*f)(int,int), int a, int b)`，把 `add`/`sub`/`mul` 轮流当参数传进去。这就是「回调」的最小骨架。
5. 故意写一行 `int *op2(int, int);`（少了括号），看编译器怎么报，把报错原文抄进注释里。
   —— 这一行是本周最容易踩的坑，先撞一次便宜的。

## Day 4（11/06 周五 · 1.5h）函数指针数组 = 跳转表

**学什么**
- **跳转表**：`void (*table[4])(void) = {led_on, led_off, beep, reset};`
  命令号 → 表下标 → 直接调。**比一长串 `switch-case` 短、好加、好维护。** 这是固件里命令分发器的原型。

**动手**（新文件 → `week4/cmd_table.c`）

1. 写四个无参函数，各自 `printf` 一句自己的名字（`led_on` / `led_off` / `beep` / `reset`）。
2. 建表：`void (*table[4])(void) = {...};` —— 声明时先照规矩从内往外读一遍，把读法写注释。
3. `void dispatch(int cmd)`：`if (cmd < 0 || cmd >= 4) { printf("bad cmd\n"); return; } table[cmd]();`
   —— **越界检查必须有**，这就是固件里「非法命令不得跳飞」。
4. `main` 里 `for (int i = -1; i <= 4; i++) dispatch(i);`，看 `-1` 和 `4` 被挡住、0~3 正常执行。
5. 把 `table` 换成 `const` 版本 `void (*const table[4])(void)`，编译一次，注释说明为什么固件里表通常是 `const`（放 Flash，不占 RAM）。

## Day 5（11/07 周六 · 4h）跳转表补完 + 回调注册表

**上午（2h）· 让跳转表"能挂东西"**
1. （追加到 `week4/cmd_table.c`）把函数签名升级成 `void (*)(int arg)`，命令带一个参数。
2. 加一个命令名表 `const char *cmd_name[4]`，`dispatch` 执行前先打 `[cmd] led_on(arg=3)`。
   —— 两张表下标对齐，这就是「命令表」的全部秘密。
3. 测试：`-1 / 4 / 0~3` 全覆盖。

**下午（2h）· 回调注册表**
4. 新建 → `week4/callback.c`：
   - 定 `typedef void (*event_cb)(int event);`
   - `static event_cb s_cbs[4] = {0};`（**静态数组，全程不用 malloc**）
   - `int register_cb(event_cb cb)`：找第一个空位放进去，满了返回 -1（**返回值代表什么，先写注释**）
   - `void fire(int event)`：遍历非空槽位依次调用，打「槽 i 被调用」
5. 注册 2 个回调 → `fire(1)` 看两个都响应；注册满 4 个后再注册 → 返回 -1；`fire` 一个没人注册的槽 → 安静跳过。
6. 想一句：**如果中断里来事件，为什么这种"表 + 注册"比 switch 更安全？** 写进文件头注释（一句话）。
